# EXECUTION PLAN 6: Close the Phase 5 residual gaps

Status: DRAFT for approval (2026-10-15). Orchestration 6. Phase 6 (arrow and spatial) becomes orchestration 7 and is not in this plan.

## Goal & Scope

**Goal.** Close the gaps the Phase 5 final gate recorded, so the Phase 6 work starts from a verified baseline: prove mid-stream interruption and token-expiry behavior offline, fix the size-mismatch panic-style error, extend the live suite to multi-chunk and GeoTIFF content, and validate the CI workflow after the first push.

**In scope**
- Mid-stream interruption: a loopback fault server that drops a connection mid-body (offline).
- Token expiry: an offline check that an expired or rejected access token produces a clear error that does not leak the token.
- Size-mismatch error text: the hf-xet size-mismatch failure surfaces as a panic-style message; map it to a clear R error (product change, user-approved).
- Larger live fixtures: a 16 MiB multi-chunk binary and a 512x512 Float32 GeoTIFF, uploaded by the user to `brownag/rxet-test-data` at the dataset top level (no subfolder); live tests pin their hashes.
- CI: validate the workflow after push (install, cache, Windows compile, check run); record the result.
- Docs: README.md stale registry sentence; testing docs for the new fixtures.

**Out of scope (explicit deferrals)**
- Phase 6 arrow and spatial features (orchestration 7).
- Live token refresh automation: the expiry test is offline; a live expiry run stays manual.
- Upload to a Hugging Face repository (decision D4 of Phase 5 stands: local server only).
- Publication or release (Phase 7 of the master plan; needs separate approval).
- Any change to the 13 exports, experimental labels, or ADR 0001.

**Verbatim constraints (carried)**
- Phase 5: "Run live tests on demand (Recommended)" — live tests run only with `RXET_LIVE_TESTS=1`.
- Phase 5: "Retire network claims (Recommended)" — no mock-backend tests come back.
- Phase 5: "Fix it now (Recommended)" for product defects found by tests (the size-mismatch fix follows this rule).
- User, 2026-10-15: "can we generate it and i will upload. you determine the specs and give me the file to upload".
- User, 2026-10-15: "Yes I can set up the token/have one ... fine grained for just this test repo" — the token lives in `.env`, is never printed, never written to a file.

## Judgment calls (flagged for review)

- **J1.** The fault server is written in R (serverSocket) because the local `local_cas_server` cannot inject faults. Spike 6.1.1 confirms the reconstruction response format from `xet-client-1.7.0` source before the server is written.
- **J2.** The token-expiry test uses the server's rejection status (401/403) plus an expired-token payload; it does not wait for real expiry. Live expiry is manual.
- **J3.** The size-mismatch fix maps the specific hf-xet failure to an R error in `R/` or `src/rust/src/lib.rs` (decided by the spike). Error text changes are called out in STATE_6.
- **J4.** Live fixture constants are pinned as literals in `test-live-hf.R`, with a comment naming the generation seed and the `SHA256SUMS.txt` values.

## Hazards

- **H1.** CI cannot be run locally. 6.5.1 records "not validated" until a push produces a run.
- **H2.** `HF_TOKEN` and the exchanged accessToken must never be printed or written to a file. Every check greps tracked files for token-shaped strings.
- **H3.** The accessToken expires; long live runs may fail mid-run. Recorded as a known limit, not fixed here.
- **H4.** `R CMD check` must use the correct override name `_R_CHECK_FORCE_SUGGESTS_` (fixed in commit 3787429).
- **H5.** Generated build outputs `src/Makevars` and `src/entrypoint.o` are restored before every commit and never staged.
- **H6.** Fault-injection tests use short timeouts; a timeout is never widened to make a failure pass.
- **H7.** Uploaded fixtures are verified by hub tree oid and size before any live constant is pinned.

## Task specs

### 6.0.1.fixture-upload

- **Owner:** user uploads; orchestrator verifies.
- **Steps:** (1) User uploads `multichunk_16mib.bin` and `geotiff_512x512_utm33n.tif` to `brownag/rxet-test-data` at the dataset top level (no subfolder). (2) Orchestrator reads the hub tree API (anonymous GET, no token printed) and checks size equals 16777216 and 1051299 bytes, and the oid equals the LFS sha256 in SHA256SUMS.txt. (3) Orchestrator records the Xet hash for each file (via the read-token path, status and hash only) into STATE_6.md.
- **Acceptance:** both files listed with matching size and oid; Xet hashes recorded. If storage is not Xet (no Xet hash), STOP and report.

### 6.1.1.spike-cas-format

- **Files:** `planning/STATE_6.md` (report only). No repo code changes.
- **Spec:** Read `~/.cargo/registry/src/*/xet-client-1.7.0/src/cas_client/simulation/` and `remote_client.rs` (grep for `reconstruction`, `term`, `Unauthorized`, `size`). Record: reconstruction JSON fields; term URL and range format; HTTP status used for an expired or invalid token; the exact error text that a size mismatch produces (reproduce with `test-local-failures.R` line ~76 under `RXET_LOCAL_CAS_SERVER`).
- **Acceptance:** STATE_6.md section "6.1.1" lists those four facts, each with a file and line reference.

### 6.1.2.size-mismatch-fix

- **Files:** `src/rust/src/lib.rs`, `R/download.R` (only if the mapping must live in R), `tests/testthat/test-local-failures.R`.
- **Depends on:** 6.1.1 (exact error text and location).
- **Spec:** Map the hf-xet size-mismatch failure to an R error whose message names the expected and actual size and does not contain panic wording. Keep the existing "no truncated bytes written" behaviour. Add a test asserting the new message. Product fix: it is a STOP-and-report only if the spike shows the fix needs a dependency change (none allowed).
- **Constraints:** no new crates; no change to the 13 exports; error text change recorded in STATE_6.
- **Acceptance:** `cd src/rust && cargo check`; `cargo test --lib tests::` passes; `devtools::test(filter = "local-failures")` passes with `RXET_LOCAL_CAS_SERVER` set.

### 6.2.1.fault-server

- **Files:** `tests/testthat/helper-fault-cas.R` (new), `tests/testthat/test-fault-midstream.R` (new).
- **Depends on:** 6.1.1.
- **Spec:** A loopback R fault server (serverSocket, 127.0.0.1, random port with retry) that answers a reconstruction request with the JSON shape from 6.1.1, then sends the first half of the term body and closes. Test: `xet_download_file` errors within a bound, no destination file, no `.part` file left; `xet_stream_raw` errors and returns nothing. Skip guards: `is_compiled()`; no real endpoint.
- **Acceptance:** `devtools::test(filter = "fault-midstream")` passes; the test wall time is under 60 seconds.

### 6.2.2.token-expiry

- **Files:** `tests/testthat/test-fault-token.R` (new).
- **Depends on:** 6.2.1 (uses helper-fault-cas.R; does not edit it).
- **Spec:** Fault server answers with the rejection status from 6.1.1 for an expired token. Assert: a clear error (contains "401" or "403" or "unauthorized"), the token value does not appear in the message, no destination file. J2 applies: no waiting for real expiry.
- **Acceptance:** `devtools::test(filter = "fault-token")` passes; `grep -n "HF_TOKEN" tests/testthat/test-fault-token.R` is empty.

### 6.3.1.live-fixtures
