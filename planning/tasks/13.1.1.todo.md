# 13.1.1 -- Rust: reader owns size; reader-id constructor; reader probe
## Goal
Make the Rust reader the single owner of file size: `xet_stream_connection` takes a reader id and close_fun, and a new `xet_reader_is_open` probe reports registry membership.

## Notes
- `xet_open_reader` already takes `file_size` and builds `WindowedReader::new(.., size)`; unchanged.
- `READERS` is `Registry<WindowedReader<XetStreamSource>>`; `Registry::acquire` returns `Result<Option<Arc<T>>, String>`, no lock held after return. Locking and window constants are untouched.
- D8 (trait-object registry) and the memory reader are NOT part of this task; the probe works on the current concrete registry.
- Risk: the build will not link cleanly end-to-end until 13.1.x updates `src/connection.c` for the new 3-arg `rxet_connection_new`; `cargo check`/`cargo test` do not link the C file, so acceptance is unaffected. `R CMD INSTALL` would break between this task and the C task.
- Risk: `#[extendr]` fn called directly from `crate::tests` should work (child module sees parent's private items; no R runtime needed for a registry lookup). If the extendr macro makes the plain fn unusable in tests, I will stop and report.
- Wrappers (`R/extendr-wrappers.R`) are not regenerated here (13.1.2).
