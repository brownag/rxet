## Notes

**Insertion points (current file, pre-edit):**

- `fn xet_stream_range` (starts line 158): loop at lines 216–219, `Ok(buf.into_robj())` at line 221. Insert the check at line 220 (after line 219).

**Exact checks and messages:**
- `xet_stream_raw`: `if buf.len() as u64 != size_bytes { return Err(Error::Other(format!("stream returned {} bytes, expected {} for hash {}", buf.len(), size_bytes, file_hash))); }`
- `xet_stream_range`: `if buf.len() as u64 != size { return Err(Error::Other(format!("stream returned {} bytes, expected {} for hash {}", buf.len(), size, file_hash))); }`

**Why the check cannot misfire on the success path:**
- `xet_stream_raw` requests the full file (`None` range), so a correct full read yields exactly `size_bytes` bytes.
- `xet_stream_range` requests `start..end`, so a correct read yields exactly `end - start` = `size` bytes.
- A check that fails only when counts differ therefore passes for every correct read. The existing `local-download` range-boundary tests exercise this and are in the acceptance filter.

**Constraints honored:** only `src/rust/src/lib.rs` is edited; no new crate, `#[allow]`, feature gate, extendr signature change, or module-list change; no token text in messages; no commit; no `git checkout`/`git restore`; no staging of `src/Makevars` or `src/entrypoint.o`.

**Risks:**
- Zero-size file: `size_bytes` = 0, the stream yields no chunks, `buf` is empty, and `0 == 0` passes. `try_reserve_exact(0)` is already a no-op. Must pass; any test for it must not be expected to error.
- If xet-core's range stream returns chunk data beyond `start..end` (not trimmed), valid range reads would now error. The `local-download` boundary tests in the acceptance filter are the detector; if they fail, STOP and report rather than altering the check.
- `devtools::test` may or may not recompile the Rust library; see Questions.
