## Notes
- Analysis (R 4.6.1, read-only check): on an already-closed connection, `isOpen(conn)` errors with `invalid connection`, and so does a second `close(conn)`. So the `tryCatch` around `isOpen()` is required, not optional.
- `R/arrow.R` lines 81-86 already use the same idea: `tryCatch(close(conn), error = function(e2) NULL)` after `arrow::read_parquet()` closes the connection. This task changes only `R/connection.R`.
- `xet_open_connection()` returns `rawConnection(raw_bytes, open = "r")`. The new tests use `rawConnection()` directly, so they stay offline and do not need `is_compiled()` skips.
- Constraints honored: roxygen for `xet_close_connection` unchanged, `man/*.Rd` untouched, no other function changed.
- Risk: `tryCatch(isOpen(conn), error = function(e) FALSE)` also treats a non-connection argument (for example an integer) as closed and returns silently. Previously that case errored. See question 1.

## Questions
1. The spec's `tryCatch` maps any `isOpen()` error to "closed". That also hides wrong-type input, such as `xet_close_connection(1)`. Should I narrow it so only an "invalid connection" error is treated as closed, and re-raise others? Default if no answer: keep the simple `FALSE` mapping per spec.
2. The spec says "closed by arrow". Arrow is optional (Suggests) and may not be installed in the test environment. Default: use a caller-side `close(conn)` to reproduce the same closed state, with no arrow dependency. Confirm, or ask for a `skip_if_not_installed("arrow")` test too.
