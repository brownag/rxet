## Notes
**Why a child process.** `xet_download_file` and `xet_stream_raw` block the R session. An in-process `serverSocket` loop cannot answer while the call is blocked. The server runs as a `processx` child running `Rscript <script>`. `processx` is already in Suggests and used by `helper-local-cas.R`. Do not use `callr`, which is not in Suggests.

**Startup and readiness.** The parent picks a port with `fault_free_port()` and passes it as an argument. The child calls `serverSocket(port)`. On success it writes a ready marker to a `tempfile()` file. The parent polls for that file, not with a TCP probe. A probe would use up the single accept. On bind failure the child exits non-zero, so the parent sees `!proc$is_alive()` and retries on a new port, up to 20 times. This matches `start_local_cas()`.

**Shutdown.** `on.exit(stop_fault_cas(h), add = TRUE)` kills the child and unlinks its temp files, whatever the outcome.

**No forever block.** Three bounds, in order:
1. The client reads with `HF_XET_CLIENT_READ_TIMEOUT=2s` and `RETRY_MAX_ATTEMPTS=1`. If the server ever stops sending, the client fails in seconds.
2. The child sets a 5 s timeout on each accepted connection (`socketAccept(timeout = 5)`) so its own reads cannot hang.
3. The child exits on its own after a lifetime deadline (say 120 s), checked between accepts. The parent kill is the normal path. The 60 s test bound is the assertion. Do not widen any timeout to make a failure pass (H6).

**Request handling.** The child reads request headers to the blank line, then dispatches on path:
- `GET /v2/reconstructions/...` returns 404, so the client falls back to V1 (verify, step 1).
- `GET /v1/reconstructions/...` returns the JSON below.
- `GET /xorb/...` (any path under the signed `url`) returns the term body.
The child serves connections in a loop until killed. Each test makes at most a few connections.

**Exact JSON for V1 reconstruction.** `FAULT_HASH <- strrep("ab", 32)` (64 hex characters). `PORT` is the child's port.
```json
{
  "offset_into_first_range": 0,
  "terms": [
    {"hash": "<FAULT_HASH>", "unpacked_length": 65536, "range": {"start": 0, "end": 1}}
  ],
  "fetch_info": {
    "<FAULT_HASH>": [
      {"range": {"start": 0, "end": 1},
       "url": "http://127.0.0.1:<PORT>/xorb/term",
       "url_range": {"start": 0, "end": 65535}}
    ]
  }
}
```
Field meanings come from 6.1.1: `terms[].unpacked_length` is used for validation; `range` is the chunk range `[start, end)`; `url_range` is the inclusive byte range. Build the JSON with `jsonlite::toJSON(..., auto_unbox = TRUE)` only if `jsonlite` is available in the child. Otherwise write the string by hand with `sprintf`, which avoids the dependency.

**How the term body length is chosen.** `N = url_range$end - url_range$start + 1 = 65536`. The response is `HTTP/1.1 200 OK` with `Content-Length: N` and `Connection: close`. The child writes exactly `floor(N / 2) = 32768` bytes (zeros, `as.raw(0)`), then closes. The client sees EOF before `N` bytes, which is the mid-stream drop. Choosing `N` equal to the file size keeps `xet_download_file` and `xet_stream_raw` aligned on the same 65536 bytes.

**Expected failure.** The term bytes are zeros, not a valid xorb. The client may reject them as garbage before it notices the short read. Either way the call errors. The test checks the error, not its text (see the TODO that records the actual text).

**Windows.** `serverSocket` and `socketAccept` are base R and work on Windows. The existing `blackhole()` in `test-phase4-lifecycle.R` already uses `serverSocket` in CI on Windows, so there is precedent. Risks to watch: the child runs `Rscript`, so use `file.path(R.home("bin"), "Rscript")` and let `processx` resolve the `.exe`. Port reuse can fail on Windows because of TIME_WAIT, which the retry loop covers. Loopback firewall prompts are not expected.

**Files.** Temp files live under `tempfile()` only. Nothing is written to `local_cas_data/`. The test does not use `local_cas_server`. The env var in the acceptance command is harmless and keeps the command uniform with the other filters.
