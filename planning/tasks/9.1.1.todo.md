## Notes
- Reference: `tests/testthat/test-fault-token.R` lines 7 (`TOKEN_CANARY`), 104-162 (`run_token_case` and 401 tests), `expect_false(grepl(TOKEN_CANARY, msg, fixed = TRUE))`.
- `test-fault-token.R` helpers (`start_token_cas`, `token_server_lines`, `run_token_case`) are file-local. Testthat does not share them across test files, so the new file must carry its own copy. `helper-fault-cas.R` is locked, so no edits there.
- Token server already supports `term_status` 401 or 403: the `/xorb/` branch writes `HTTP/1.1 %d Unauthorized`. A 403 response will report "Unauthorized" in the status line; the test only checks the status code in the request log.
- Fault server routes: `/v2/` -> 404, `/v1/reconstructions/` -> JSON, `/xorb/` -> 401/403 or truncated body. No upload routes, so `xet_upload_file` cannot reach a network 401 here.

- `xet_upload_file` (R/upload.R:24) errors on a missing file before `.Call`. That is the only offline upload path.
- Optional packages arrow, terra, sf and processx are installed on this machine.
- Constraints honored: no edits to product code, `man/`, `helper-fault-cas.R`, or `.env`. No token printed. No commit. Success paths are not asserted.
