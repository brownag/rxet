# 8.3.1 final review (static, read-only)

Range: `17f615f..HEAD`. Product diff: `R/arrow.R`, `R/spatial.R`. Unchanged in range but reviewed at HEAD: `R/connection.R`, `R/stream.R`, `R/utils.R`. Docs: `NEWS.md`, `README.Rmd`, `docs/decisions/0001-public-api-support-contract.md`.

Not run: `R CMD check`, `devtools::test`, live suite, `.env`. Every finding is from reading code, tests and docs. Token findings are labelled static.

## Findings

- severity: high
  - file:line: `NEWS.md:75`
  - scenario: The release notes end with the placeholder `TEST_EVIDENCE_PENDING`. If shipped, the 0.1.0 notes publish an unfilled section.
  - fix: Fill the "Test evidence" section from the final gate output in `planning/STATE_7.md` (routine suite counts and the clean `R CMD check` result), or remove the heading before tagging. Owner: orchestrator.

- severity: medium
  - file:line: `NEWS.md:71`, `README.Rmd:57`, `README.Rmd:233`; test scope at `tests/testthat/test-fault-token.R:123-163`
  - scenario: Both docs say rxet "does not write the token into its error output" with no qualifier. The canary test checks only the 401 path of `xet_download_file()` and `xet_stream_raw()`. Static read: no `format!` in `src/rust/src/lib.rs` references `client.token`, and the R validation at `R/client.R:43` reports only the expression text, so the claim holds for the reviewed paths. But a token echo on any other path, such as `xet_open_connection()`, `xet_stream_range()`, `read_xet_*()`, `xet_upload_file()`, or a 403 or network error, is not caught by any test. The hf-xet crate's own logging is not reviewed.
  - fix: Either narrow the claim to "checked for the token-expiry path" in both docs, or extend the canary test to every entry point that takes a token. Label the claim "static" until then.

- severity: medium
  - file:line: `R/arrow.R:28`, `R/arrow.R:114`, `R/spatial.R:21-22`, `R/spatial.R:125-126`
  - scenario: The memory claims ("about one copy of the file plus the parsed object"; "about the file bytes plus the in-memory raster values") count fewer copies than the code makes. `read_xet_raster` and `read_xet_vector` hold `raw_bytes` from `xet_stream_raw()`, the `rawConnection` buffer, and the `bytes` vector from `readBin()` at the same time, then write the temp file. `rawConnection()` may duplicate its input, which would add another copy. Not measured.
  - fix: Measure peak memory on the 16 MiB fixture, or reword to "roughly two to three copies of the file during the load". Update the same text in NEWS.md if it is repeated there.

- severity: low
  - file:line: `R/spatial.R:173-177` (`tempfile()` with no extension); `R/spatial.R:118` ("And 80+ other formats")
  - scenario: `read_xet_vector()` writes an extensionless temp file. GDAL drivers that identify a format by file extension, such as CSV with geometry columns, may not open it, even though the roxygen lists formats as supported. Not run.
  - fix: Keep the extension in the temp name (for example, take it from a user argument or document content-identified formats only), and drop or qualify "80+ other formats".

- severity: low
  - file:line: `R/arrow.R:83-88`; `tests/testthat/test-arrow-spatial.R` (no `isOpen` assertion)
  - scenario: `read_xet_parquet()` on success depends on arrow closing the `rawConnection` (`R/arrow.R:20-21`, `R/arrow.R:83-88`). If a future arrow version stops doing that, the connection stays open until garbage collection. Grep found no `isOpen` assertion in `tests/testthat/test-arrow-spatial.R`.
  - fix: Add a test that the connection is closed after a successful `read_xet_parquet()`, or close it explicitly after success and rely on the error-path handler only if arrow is confirmed to close.

- severity: low
  - file:line: `planning/STATE_7.md` Residual gaps, last bullet (not in the release diff)
  - scenario: STATE_7 still lists "if `readBin` errors inside `read_xet_raster`/`read_xet_vector`, the connection is not closed". The code registers `on.exit(close(conn))` before `readBin` (`R/spatial.R:82` and `R/spatial.R:170`), and `test-arrow-spatial.R:124` covers the error path. The residual gap is stale.
  - fix: Orchestrator updates the residual list. This review does not edit STATE_7.

- severity: low
  - file:line: `R/connection.R:81-83`
  - scenario: `xet_close_connection(conn)` calls `close(conn)` without checking `isOpen()`. A second call, or a call on a connection that was already closed by arrow or by the caller, errors with "invalid connection". Documented as "closes the connection" with no mention of this.
  - fix: Guard with `if (isOpen(conn)) close(conn)`, or document that it errors on a closed connection.

- severity: low
  - file:line: `R/utils.R:165-180` (`make_hf_api_request`, HEAD-state)
  - scenario: The function takes the bearer token and returns `as.character(e)` in its result. Grep finds no callers (only the definition), so it is dead code. If a future caller logs the result, the error path could carry the token. Static finding.
  - fix: Delete the function if still unused, or keep its error text free of request headers.

- severity: low
  - file:line: `DESCRIPTION:30` (Suggests `uuid`); `tests/testthat/test-edge-cases.R:110,115`; `.github/workflows/R-CMD-check.yaml` (no `uuid`)
  - scenario: The audit's residual gap is confirmed. `uuid` is in Suggests and used by a test, but CI does not install it, so `skip_if_not_installed("uuid")` skips the test silently in CI.
  - fix: Add `uuid` to the CI `extra-packages`, or accept the skip and note it in the release notes.

- severity: low
  - file:line: `AGENTS.md:208`
  - scenario: The layout comment says `msrv.R` validates "Rust version >= 1.70". The enforced minimum is 1.85.0 (from `DESCRIPTION` SystemRequirements, as the 8.1.1 audit shows). AGENTS.md is not in the release diff, but a new contributor reads it.
  - fix: Change the comment to ">= 1.85.0" or "minimum from DESCRIPTION SystemRequirements".
