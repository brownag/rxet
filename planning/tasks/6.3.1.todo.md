**Expected behaviour.** The pinned values are the only expectations. Range and stream results are compared with bytes from the full download, not with bytes computed by hand. Range ends are end-exclusive (per the existing PAR1 test). Gate: `RXET_LIVE_TESTS=1` and `is_compiled()`; with the gate unset the four new tests skip, never error.

**Helper.** `start_live_client()` is reused unchanged. It creates a private `HF_HOME` per test and removes it at exit, so the developer's shard cache is never read or written. `live_cas_token()` is not changed.

**Probe token state.** The existing probe test already reports only `HF_TOKEN set|unset`. No change is needed there. The token must not appear in STATE_6 or in any printed output.

**Risks.**
- The 16 MiB download can be slow on a cold connection. Each new test starts a fresh client and a fresh shard cache, so every test pays the full download. If the run is too slow, the fix is a shared download in a single `local` helper, which is out of this task's scope unless the user asks.
- The accessToken from `live_cas_token()` expires (H3). If the run fails mid-way with an auth error, record it as a finding; do not retry in a loop.
- Chunk boundaries are content-defined and are not exposed to R. Offset 65536 is "not the start of the file", not a verified chunk boundary. Do not claim a boundary in test names or STATE_6 unless it is verified.
- `grep` cannot redact; the pipe uses `sed` for the redaction. Hashes are not secret and are shown in output.
- Test (b) downloads the file again, which doubles the 16 MiB transfer. Reusing (a)'s `dest` would need a shared fixture and is avoided here for isolation.
