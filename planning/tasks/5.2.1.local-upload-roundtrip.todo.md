## Notes

Facts (read-only, verified 2026-10-15):
- `R/upload.R` lines 1-33: `xet_upload_file(handle, src_path)` checks `stopifnot` on types, then `if (!file.exists(src_path)) stop(sprintf("source file does not exist: %s", src_path))`, then `.Call("wrap__xet_upload_file", handle, src_path, PACKAGE = "rxet")`. The missing-source error is R-side, so no server call is made.
- `src/rust/src/lib.rs` line 264: `fn xet_upload_file(handle: &str, src_path: &str)`. Uses `new_upload_commit`, `upload_from_path_blocking(src, Sha256Policy::Skip)`, `commit_blocking`. Errors unless `report.uploads.len() == 1`. Returns `list!` with hash and file_size from the upload metadata.
- `tests/testthat/helper-local-cas.R`: `skip_without_local_cas()` (line 35), `start_local_cas()` (line 77, returns `list(endpoint, proc, files)`), `stop_local_cas(handle)` (line 107, safe to call twice), `make_fixture_bytes(n, seed = 1L)` (line 116), `upload_fixture(client, bytes)` (line 122, returns `list(hash, file_size, sha256)`), `assert_roundtrip(client, bytes)` (line 136).
- `test-local-cas-harness.R` pattern: `context(...)`, `test_that`, `skip_without_local_cas()`, `h <- start_local_cas()`, `on.exit(stop_local_cas(h), add = TRUE)`.
- Server facts (STATE_5.md 5.0.1): binary `$HOME/.cargo/bin/local_cas_server` (not on PATH); `--in-memory` used by the harness so nothing is written to disk; unknown reconstructions return HTTP 416, not 404.
- Plan for test seam: use `upload_fixture()` for the upload step so the helper stays the single source of upload calls. Download via `xet_download_file(client, hash, file_size, dest)`.
- Empty-file probe approach (spec step 4): probe first in the scratchpad (TODO 3), then write the test to assert exactly what was observed: success path asserts `file_size == 0` and byte identity of `raw(0)`; error path asserts `expect_error()` with the observed message fragment. The title names the pinned behavior. No guessing.

Constraints honored:
- Only `tests/testthat/test-local-upload.R` is created. No `R/**`, `src/**`, `DESCRIPTION`, helpers, or other tests are edited.
- No HF upload, no `HF_TOKEN`, data only in `tempfile()`, `--in-memory` server.
- No commit, no `git checkout` / `git restore`, no staging of `src/Makevars` or `src/entrypoint.o`.

Risks:
- Upload path through the local server: the upload commit could fail for the 4 MiB case or report a different `uploads` count. TODO 4 probes this before pinning.
- 416 response: a missing reconstruction returns 416. Not exercised here, because 5.3.1 owns failure paths. If the upload path ever calls for a reconstruction and gets 416, it will surface as an error, and this task will STOP and report.
- Empty-file behavior: unknown until probed. Possible outcomes are success with size 0 or an error from the upload or commit step. The test pins what is observed and does not assume either.
- `devtools::load_all` in TODO 3, 7 may rebuild `src/Makevars` and `src/entrypoint.o`. These are already modified from 5.1.1. Not restored, not staged (see Questions 1).
