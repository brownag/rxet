**Proposed `Registry<T>` API (`src/rust/src/registry.rs`):**
```rust
pub struct Registry<T> { inner: Mutex<HashMap<String, Arc<T>>> }
impl<T> Registry<T> {
    pub fn new() -> Self;
    pub fn insert(&self, key: String, value: T);
    pub fn acquire(&self, key: &str) -> Option<Arc<T>>;
    pub fn remove(&self, key: &str) -> Option<Arc<T>>;
}
```
- `lazy_static` remains usable: `lazy_static!` only requires `Registry<XetClient>: Sync`. That holds because `Mutex<HashMap<String, Arc<T>>>` is `Sync` when `T: Send + Sync`, which the current `Mutex<HashMap<String, Arc<XetClient>>>` already requires. No `Lazy` / `once_cell` needed.
- `T` is unbounded on the struct and `impl`. Only `Sync`/`Send` bounds come from the static.
- `new` is not `const`; `lazy_static` does not need it to be.
