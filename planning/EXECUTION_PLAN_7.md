# EXECUTION PLAN 7: Phase 6 — optional integrations and memory behaviour

Status: DRAFT for approval (2026-10-16). Orchestration 7 implements master plan Phase 6. Phase 7 (release validation and publication) is a later orchestration and is not in this plan.

## Goal & Scope

**Goal.** Make the optional arrow, terra and sf helpers honest and tested: each retained helper has behaviour and memory use that match its name and documentation, its tests read real downloaded bytes, and optional packages are guarded by `requireNamespace()` and declared in Suggests.

**In scope**
- Four exported helpers: `read_xet_parquet`, `read_xet_parquet_stream`, `read_xet_raster`, `read_xet_vector`.
- Test coverage of each helper against committed fixtures, served by the local CAS server.
- Documentation of whole-download behaviour and peak memory for each helper.
- Enforcement of the 2 GiB in-memory cap on the connection path these helpers use.
- Committed small fixtures with provenance.

**Out of scope (explicit deferrals)**
- A true range-backed or seekable connection. Master plan item 4 requires a separate design with an interface and protocol investigation. Not in this plan.
- Phase 7 release validation, release notes, tagging, publication.
- Live-suite changes beyond what is needed to keep existing live tests green.
- Any change to the 13 exports, to the experimental labels of the four helpers beyond what is listed below, or to ADR 0001.

**Verbatim constraints (carried)**
- User, 2026-10-16: "keep, but as not hard dependencies (tho most everything needs at least sf); yes we can install arrow". arrow, terra and sf stay in Suggests and are never hard dependencies.
- Master plan Phase 6, item 4: "do not bolt it onto rawConnection helpers as a documentation-only change."
- Master plan Phase 6, item 6: "avoid relying on locally generated mutable test data."

## Judgment calls (flagged for review)

- **J1.** The 2 GiB cap is already enforced in `xet_stream_raw` and reached through `xet_open_connection` (`R/connection.R:60`). Task 7.2.1 proves it for the helpers instead of adding a second check.
- **J2.** Fixtures are generated by a script committed beside them, so the bytes can be regenerated and checked. The script uses fixed seeds and writes no network data.
- **J3.** The fixture for `read_xet_raster` is a tiny GeoTIFF and the fixture for `read_xet_vector` is a small GeoJSON. Both are plain-text or small binary and are committed directly.

## Hazards

- **H1.** Local arrow, terra and sf versions are current CRAN. A later version may change behaviour; the tests will show it, not the docs.
- **H2.** `read_xet_raster` and `read_xet_vector` may write temporary files. Tests must use `tempfile()` and clean up.
- **H3.** Fixtures must stay small (under 100 KB each) to respect repository policy.
- **H4.** `HF_TOKEN` is never needed in this plan. Tests here use the local server only.
- **H5.** Generated build outputs `src/Makevars` and `src/entrypoint.o` are restored before every commit and never staged.

## Task specs

### 7.1.1.spike-helper-paths

- **Files:** `planning/STATE_7.md` (report only).
- **Spec:** Read `R/arrow.R` (lines 55-135), `R/spatial.R` (lines 58-139) and `R/connection.R` (lines 40-84). For each helper record: the read path (in memory or temp file), whether a temp file is created, and the call that reads the connection. Confirm that the 2 GiB refusal is reached through `xet_open_connection` (`R/connection.R:60`) by calling it with a size above the cap; expect the refusal before any network call.
- **Acceptance:** STATE_7 section "7.1.1" lists the four helpers, each with file:line references and the refusal text.

### 7.1.2.fixtures

- **Files:** `tests/testthat/fixtures/make_fixtures.R`, `tests/testthat/fixtures/PROVENANCE.md`, and the three generated files.
- **Spec:** `make_fixtures.R` writes `small.parquet` (a few rows, two columns), `small.geojson` (three features with a CRS note), and `small.tif` (a 16x16 Float32 GeoTIFF). Fixed seeds. Each file under 100 KB. `PROVENANCE.md` records the generator, the R and package versions, and a licence statement (CC0 for generated data).
- **Acceptance:** `Rscript tests/testthat/fixtures/make_fixtures.R` run from a scratch directory produces the same SHA-256 hashes as committed (checked against `PROVENANCE.md`); each file is under 100 KB.

### 7.2.1.arrow-tests

- **Files:** `tests/testthat/test-arrow-spatial.R` (arrow section), `tests/testthat/helper-fixtures.R` (new).
- **Depends on:** 7.1.1, 7.1.2.
- **Spec:** Helper uploads the fixture to the local server (`upload_fixture`, the existing helper) and returns the hash and size. Tests: `read_xet_parquet` returns a data frame equal to the one written by `make_fixtures.R`; `read_xet_parquet_stream` returns a connection whose bytes equal the downloaded file; a file size above the 2 GiB cap is refused with a message that names `xet_download_file`. Skip cleanly when arrow is absent.
- **Acceptance:** `RXET_LOCAL_CAS_SERVER=$HOME/.cargo/bin/local_cas_server Rscript -e 'devtools::test(filter="arrow-spatial")'` shows the arrow tests passing (arrow installed here).

### 7.2.2.spatial-tests

- **Files:** `tests/testthat/test-arrow-spatial.R` (terra and sf sections only).
- **Depends on:** 7.2.1 (same file; wave 3).
- **Spec:** Tests: `read_xet_raster` on the GeoTIFF returns a SpatRaster with the fixture's dimensions and values; `read_xet_vector` on the GeoJSON returns an sf object with three features. Skip cleanly when terra or sf is absent. Any temporary file is removed.
- **Acceptance:** same command as 7.2.1; the terra and sf tests pass locally.

### 7.3.1.helper-docs

- **Files:** `R/arrow.R`, `R/spatial.R` (roxygen comments only), `AGENTS.md` (new "Optional integrations" section).
- **Depends on:** 7.2.1, 7.2.2.
- **Spec:** Each helper's roxygen states: whole-download (the file is fully read before the call returns), peak memory of about one copy of the file plus the parsed object, the 2 GiB refusal, and that arrow, terra or sf are Suggests and checked with `requireNamespace()`. `read_xet_parquet_stream` is titled as a whole-download helper, not a streaming helper. No code changes.
- **Acceptance:** `git diff -- R/` shows only comment lines; `git diff -- NAMESPACE DESCRIPTION` is empty; the orchestrator runs `roxygen2::roxygenise()` after the wave and `git diff -- NAMESPACE` is empty.
